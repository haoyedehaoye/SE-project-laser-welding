# LaserWelding · 激光焊接机械臂数据平台

本项目计划把四路数据汇入主机：STM32 的电流/电压、热像仪的温度矩阵、机械臂电柜的焊接速度/时间，以及工业相机的焊接视频。目标是在前端显示焊接过程，并在取得真实故障与维修标签后训练和展示预测性维护结果。

> 当前阶段：`test/` 是持续开发和硬件联调的实验区；`app/` 是正式系统代码。现有 XGBoost 模型预测窗口异常、裂纹和焊缝几何，**尚不能预测机械臂故障或剩余寿命**。详细进度见 [项目现状与目录说明](docs/09_项目现状与目录说明.md)。

## 当前能力

| 数据/能力 | TEST 实验区 | APP 正式系统 |
| --- | --- | --- |
| STM32 电流/电压 | 旧 TCP 模拟协议侧重温度、 电压和状态位；不能等同于目标电流/电压协议 | 串口解析器和 HTTP 接口已写；默认未启用串口，真实协议待确认 |
| 温度矩阵 | TCP 接收、原始帧解码和二维热图已写 | 接收接口和内存中的最新矩阵已写；前端尚无热图 |
| 焊接速度/时间 | 暂无电柜数据接入 | HTTP 接口已写；暂无电柜协议适配器 |
| 工业相机视频 | 海康相机预览联调代码已写 | 海康 MVS 适配和浏览器预览已写；真机运行需 SDK 与相机 |
| XGBoost / 预测性维护 | 有训练、评估和质量/裂纹实验 | 模型注册和手动推理接口已写；尚无自动在线推理及维护故障模型 |

当前正式系统只在内存保留近期事件，没有四路数据的统一焊接任务 ID、长期存储和时间同步。首页主要展示视频、设备状态、数据是否到达以及手动模型分析；电流/电压曲线、温度热图、速度/时间和维护预测结果仍需实现。

每条正式 APP 采集事件包含 `captured_at`（采集时间）和 `received_at`（进入主机数据管线的时间），单位均为 Unix 秒；API 还返回对应的 `*_utc` 时间文本。前端按浏览器所在时区显示最近一次采集和接收时间。设备没有提供可确认的日历时间时，采集时间由主机标记；热像仪帧头的原始时间值单独保留，单位确认前不当作 Unix 时间使用。

## 目录

```text
app/       正式后端、数据管线和前端
test/      持续开发的实验与设备联调
tests/     正式系统的自动检查
models/    现有研究模型及其配置
config/    正式系统配置
scripts/   正式系统启动辅助脚本
docs/      研究记录、历史文档和项目现状
project_archive/ 旧代码、历史资料及运行产物
```

历史说明保存在 [`project_archive/history/`](project_archive/history/)，归档内容的原始位置见 [`project_archive/README.md`](project_archive/README.md)。历史文档反映当时的阶段，不作为当前启动说明。
