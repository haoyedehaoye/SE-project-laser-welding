# 现状盘点与正式化迁移清单

> 阶段：第一阶段（项目盘点）  
> 日期：2026-09-10  
> 结论：`test/` 是当前唯一可运行的 Python 单体应用；`acquisition/` 与 `processing/` 是尚未贯通的生产骨架，不能通过简单复制完成正式化。

## 1. 第一版范围

### 纳入第一版

- Windows 工业电脑运行。
- 接入海康机器人 MV-CS050-10GM/GC GigE 工业相机。
- 相机实时预览、连接状态、断线恢复。
- 视频录像、分段保存、保留三天和磁盘空间保护。
- 保留 STM32 模拟数据源，供无真实 STM32 协议时开发与联调。
- 展示机械臂运行状态、轨迹和工艺参数。
- 为机械臂控制器数据保留只读适配器和交换机监听接口。
- 保存设备数据、事件、报警、视频索引和系统日志。
- 为后续预测性维护保留数据和模型接口。
- 后续支持局域网访问。

### 第一版不做

- 焊接状态判断。
- 视觉缺陷识别与视觉质量评估。
- 合格/不合格判断。
- 自动控制机械臂或自动调整工艺参数。
- 用当前公开数据集训练正式预测模型。
- 完整生产质量追溯。

### 2.2 `acquisition/` 与 `processing/`：生产骨架

骨架包含采集器基类、STM32 串口采集器、多模态同步器、日志和 YAML 配置，但当前未贯通。

已确认的阻断问题：

1. `acquisition/base_collector.py` 导入 `utils.logger`，实际模块位于 `processing/utils/`，从项目根导入会报 `ModuleNotFoundError`。
2. `acquisition/test_stm32.py` 查找根目录 `config.yaml`，实际配置位于 `processing/config.yaml`。
3. YAML 写的是“STM32 经串口服务器和交换机接入”，采集器实现的却是本机 COM 串口。
4. 配置写了机械臂 Modbus TCP，但没有对应采集器。
5. 配置写了工业相机和热像仪，但没有相机采集代码。
6. 配置写了 SQLite 和 InfluxDB，但没有数据写入实现。

### 2.3 VS Code 扩展脚手架

## 3. 已发现的接口冲突

### 3.1 两套 STM32 帧协议

`test/collector.py` 使用 8 字节协议：

```text
AA + 温度 int16 + 电压 uint16 + 状态 uint8 + XOR + 55
```

`acquisition/stm32_collector.py` 使用 11 字节协议：

```text
AA + 电压 float32 + 电流 float32 + XOR + 55
```

两者字段、字节序、长度和通信方式均不同。正式版应把“传输方式”和“协议解析”分离：

- 数据源负责 TCP、串口或未来交换机监听；
- 协议解析器只负责把字节流变成标准数据；
- 在真实 STM32 协议确定前，第一版继续支持现有 TCP 模拟协议。

### 3.2 两套数据模型

`test/data_types.py` 的 `DataPoint` 带 `quality`；生产骨架的 `DataPoint` 带 `metadata`，二者不兼容。

正式数据模型至少需要：

| 字段 | 含义 |
|---|---|
| `device_id` | 设备唯一标识 |
| `source` | camera / stm32 / robot / system |
| `event_type` | telemetry / status / alarm / frame |
| `captured_at` | 设备或采集端产生时间 |
| `received_at` | 系统接收时间 |
| `data` | 实际业务字段 |
| `units` | 字段单位映射 |
| `mode` | real / simulated |
| `validity` | valid / stale / invalid |
| `metadata` | 序列号、协议、原始时间等扩展信息 |

“数据有效性”不能继续叫“焊接质量”，避免与焊接质量识别混淆。

## 4. 缺失的正式能力

### 工业相机

当前只有视频状态占位接口，没有：

- 海康 MVS SDK 封装；
- 相机枚举和按序列号/IP选择；
- 取帧、像素格式转换和实时预览；
- 断线重连和资源释放；
- 录像、分段、视频索引与三天清理。

浏览器 `<video>` 不能直接播放常规 RTSP 地址，正式版必须通过后端转换为浏览器支持的视频流或连续图像流。

### 机械臂

当前没有机械臂采集器、协议适配器、轨迹模型或轨迹页面。第一版应先建立只读 `RobotDataSource` 接口与模拟实现，不假定最终协议一定是 Modbus TCP。

### 数据存储

当前只有内存环形缓冲和日志，没有正式数据库读写。SQLite/InfluxDB 仅存在于配置文本中。

### Windows 部署

当前依赖 VS Code 任务或两个终端启动，尚无统一启动器、环境检查、开机启动、异常恢复和数据目录管理。

## 5. 依赖检查

当前 `.venv` 已具备 FastAPI、Uvicorn、WebSocket、NumPy、SciPy、scikit-learn、XGBoost、OpenPyXL 和 OpenAI SDK。

生产骨架引用但当前环境未安装：

- PyYAML；
- pyserial；
- loguru；
- OpenCV。

相机接入还需要安装与相机匹配的海康 MVS Runtime/SDK，并确认 Python 可调用的动态库路径。依赖清单中目前没有相机SDK检测。

前端 ECharts 当前从公网 CDN 加载；正式部署应改为本地静态资源，保证工业局域网断网时仍能显示图表。

## 6. Git 与文件管理风险

盘点时工作区已有大量修改和新增文件，包括模型、实验文档、Python代码、日志和缓存。后续修改必须保留这些用户成果，不能通过重置或覆盖处理。

`.gitignore` 当前只排除了 Node 构建内容，后续应补充：

```gitignore

__pycache__/
*.py[cod]
logs/
recordings/
data/*.db*
```

模型和研究报告是否提交不在本阶段调整。

## 8. 第二阶段执行顺序

1. 建立 `app` Python 包和正式入口。
2. 定义统一设备数据模型与设备数据源接口。
3. 建立统一配置、日志和生命周期管理。
4. 迁移 STM32 TCP 模拟器、采集器和协议解析器。
5. 迁移 FastAPI 与 WebSocket 广播机制。
6. 建立工业相机和机械臂适配器接口空实现。
7. 建立只展示设备数据的最小页面。
8. 验证正式入口可以独立启动、停止和断线重连。

第二阶段完成的验收条件：不依赖 `test/main.py`，即可用 STM32 模拟器驱动正式后端和最小仪表盘；运行链路中不包含焊接状态、缺陷识别或质量预测。
