# 项目现状与目录说明

更新时间：2026-09-27。以下为代码、配置与自动检查的盘点；没有连接真实 STM32、热像仪、机械臂电柜或工业相机做端到端验收。

## 目标数据流

```text
STM32 电流/电压 ──────┐
热像仪温度矩阵 ───────┼─→ 主机采集 → 校验 → 按焊接任务和时间关联 → 存储 → XGBoost → 前端
电柜焊接速度/时间 ────┤
工业相机焊接视频 ─────┘
```

`test/` 用于探索协议、设备和模型；`app/` 承载正式服务。两个目录都需要保留，但不能把实验结果当成正式能力。

## 四路数据的实现情况

| 数据 | TEST（实验） | APP（正式） | 尚缺 |
| --- | --- | --- | --- |
| STM32 电流/电压 | `test/simulator.py`、`collector.py` 采用旧 TCP 帧，主要字段为温度、电压、状态；有规则/XGBoost 质检和旧仪表盘 | `app/data_collection/current.py` 可解析 11 字节电压/电流帧，支持串口或模拟；`POST /api/data/current` 可接收外部数据。`config/app.toml` 默认 `enabled=false` | 与真实 STM32 通信方式、帧格式、量程和采样率对齐；现场验证 |
| 热像仪温度矩阵 | `test/thermal_receiver.py` 接收 TMP1 帧并转发给 TEST 后端；`test/thermal_frames.py` 存最新帧并统计丢帧；TEST 首页有二维热图 | `POST /api/data/temperature/raw` 可接收原始矩阵，内存保留最新帧，并将统计值送入事件总线；另有 JSON 矩阵接口 | 当前接收器默认转发 TEST；APP 缺面向前端的最新矩阵/热图接口和实际设备部署验证 |
| 电柜焊接速度/时间 | 未找到电柜采集器 | `POST /api/data/robot` 可接收速度、累计时间并进入事件总线 | 电柜只读协议、数据采集器、单位校准和现场验证 |
| 工业相机视频 | 有海康 MVS 相机联调服务与旧仪表盘预览 | `app/devices/camera/` 和 `app/services/camera_service.py` 支持设备枚举、取帧、重连及浏览器连续图像预览 | 真机/SDK 验收、录像与索引、视频时间戳和其他三路数据关联 |

## 分析与前端

- `test/` 有合成窗口异常模型、搭接接头裂纹/几何模型的训练、评估和网页实验。这些代码仍在开发中，不应清理。
- `app/data_analysis/xgboost_models.py` 注册当前模型，并提供手动调用的工艺模型、窗口异常模型接口。模型目标为数据异常、裂纹和焊缝几何。正式数据流收到新事件后**不会自动触发这些模型**。
- `app/data_analysis/maintenance.py` 目前只报告四类数据是否到达及缺少的训练条件。没有基于故障码、维修工单或部件更换记录训练的机械臂故障概率/RUL 模型。
- `app/frontend/index.html` 显示相机画面、设备状态、四类数据到达状态、模型清单和手动工艺分析。尚未显示实时电流/电压、温度矩阵热图、速度/时间或真正的维护预测结果。
- `app/data_transport/event_bus.py` 只保留最多 2000 条内存事件。没有持久化、统一焊接 `run_id` 或四路时间同步；相机帧目前不进入该事件总线。

## 当前可验证的范围

- 正式系统自动检查：`tests/` 的 6 项通过，覆盖数据模型、配置、服务生命周期、PNG 编码和模拟相机预览。
- 温度实验自动检查：`test/test_thermal.py` 的 3 项通过，覆盖帧头解析、最新矩阵、丢帧计数和错误负载。
- 正式服务的 `/`、`/api/health`、`/api/models` 可在本机测试客户端返回 200。APP 当前没有 `/api/data/temperature/latest`，因此正式前端尚无法读取热图网格。
- 上述检查不能证明真实设备连接、四路同步或预测性维护准确率。

## 文件整理说明

- 保留 `test/`：活跃实验与硬件联调；历史 `logs/` 已移至 `project_archive/logs/test/`；TEST 再次运行时会生成新日志。
- 保留 `app/`、`tests/`、`models/`、`config/`、`scripts/`：正式运行和验证所需。
- `project_archive/early-prototype/`：原根目录 `acquisition/`、`processing/`，未进入正式运行链路，保留供协议设计参考。
- `project_archive/vscode-extension/`：原 VS Code Hello World 扩展模板及其 `node_modules/`。与 Python 监控系统无调用关系；依赖目录可在确定不再开发扩展后另行清理。
- `project_archive/history/`：整理前的 README 和旧版运行指南，保留原文供追溯。
- `.venv/` 是可重建的本地环境，但当前启动脚本直接使用它，继续保留。

## 下一步建议

1. 确定四台设备的实际协议、字段、单位和时间戳，先让正式 APP 分别接到真实数据。
2. 为 APP 增加温度网格读取与热图、电流/电压及速度/时间实时展示。
3. 给每次焊接建立 `run_id`，关联四路时间戳，并增加持久化和相机录像索引。
4. 收集故障码、维修工单和部件更换记录，定义可验证的维护预测目标；再将在线特征与 XGBoost 推理接入正式数据流。
